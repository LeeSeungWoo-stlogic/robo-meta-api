# RWIS `data_process` 글자 → VAL 처리

원천에 코드표가 없다. 구분은 `RDITAG_TB.DATA_PROCESS` 컬럼과 설계서 설명, 마트 뷰의 VAL 움직임으로 맞춘 것이다. 카탈로그 값매핑·시드팩 대상이 아니다.

서빙 차원은 `rwis_mart.vw_tag_dim`이다. 측정은 `vw_measure_1min` / `vw_measure_hour` / `vw_measure_day`다. 일·시간 표본일은 **2025-11-27**, 1분 표본은 값이 있는 **2025-09-01**이다. `tag_unit`은 차원 코드, 단위는 `UNIT_DESC`다.

VAL은 글자당 대표 태그 한 건이다. 같은 글자에 단위가 섞일 수 있다(9의 공급율, F의 %).

## 적용 순서 (decide)

1. 목록·위치·기능은 `vw_tag_dim`만 쓴다. 글자를 보지 않는다.
2. 측정값이면 자연어로 `tagsn`을 확정한 뒤, 그 행의 `data_process`를 차원에서 읽는다. 팩트 전체 스캔은 하지 않는다.
3. 글자를 처리 종류로 바꾼다. 질문(조회·합계·평균)과 조합한다.
4. 묶인 글자가 섞이면 한 `SUM`을 만들지 않는다.
5. `/data_decision`이 집계 계약으로 남긴다. `/t2sql` GENERATE는 글자표를 외우지 않고 계약만 따른다.
6. 시간 단위는 질문 언어다. M이라고 1분을 강제하지 않는다.

이 규칙은 RWIS 전용이다. 글자→처리 종류 표만 엔진의 닫힌 지식이다(권역 별칭 표와 같은 층). 차원에서 `data_process` 값을 읽는 일은 별칭 확장과 다른 경로다. 물리 테이블명 하드코딩이 아니다.
